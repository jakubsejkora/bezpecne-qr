# shared/

This folder is the single source of truth for the prototype, the iOS app and the future Android app.

| Path | What it is |
|---|---|
| `rules/weights.json` | Scoring model: engines, evidence groups, caps, signal weights and floors |
| `rules/signals.json` | User-facing texts (CZ/EN) for evidence (observation → implication → action), consequences, checks and incomplete reasons |
| `rules/tlds.json`, `brands.json`, `parking.json`, `shorteners.json`, `freehosts.json` | URL heuristics and allowlists (with sources) |
| `rules/dcb.json` | Carrier-billing hosts and the subscription-page patterns |
| `rules/cz-premium.json`, `wangiri.json` | Czech premium-rate SMS and voice rules, missed-call scam prefixes |
| `rules/state-accounts.json` | The rule that state institutions bank at ČNB (0710) |
| `rules/bank-codes-cz.json` | ČNB bank codes. Generated by `scripts/gen-rules.mjs`; don't edit by hand |
| `content/*.json` | Operator payment-blocking guide and recovery guide (CZ/EN) |
| `testdata/samples.json` | Test corpus (see below) |

## Test corpus

Each sample has these fields:
- `id`, `group`, `title` (CZ/EN);
- `scene` and `symbology` (used by the prototype and the test sheet);
- `payload`, `type`, `engine`, `fields` (the expected parse result);
- `inspection` (mocked network responses for link samples);
- `signals`, `consequences`, `checks` (IDs + arguments), `completeness`;
- `expected.band`.

Rules for the data:
- All domains, people and accounts are **synthetic**. Fictional domains were checked to be unregistered, and accounts use obviously synthetic numbers.
- Real domains appear only as official allowlist examples.
- `node scripts/gen-prototype-data.mjs` validates that every sample's computed band matches `expected.band`, that IBANs and account numbers match their fields, and that every ID has texts.

Every rule file lists its sources and its retrieval date. Re-check them before each release, because Czech operator steps, parking providers and bank codes change.
